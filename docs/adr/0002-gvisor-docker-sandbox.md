# gVisor/Docker as Agent Sandbox

We chose gVisor (`runsc` OCI runtime) with Docker SDK (`docker-py`) for agent isolation over E2B (Firecracker-based, requires cloud infrastructure for self-hosting), bubblewrap (no maintained Python SDK, requires manual egress policy), and raw Docker (insufficient isolation). gVisor provides a user-space kernel with syscall filtering while using the same Docker workflow — `docker run --runtime=runsc --rm`. This is the right point on the isolation spectrum for single-tenant, self-hosted agents (not multi-tenant SaaS executing strangers' code). Fallback to hardened plain Docker (dropped capabilities, seccomp, read-only rootfs) if gVisor's syscall compatibility causes friction with opencode serve; validate with a smoke test before committing.

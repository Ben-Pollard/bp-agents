# No Long-Lived Credentials in Agent Sandbox

LLM API keys SHALL never be stored in environment variables, files, or any persistent location inside the agent sandbox container. The orchestrator injects credentials into opencode's process memory via `PUT /auth/:id` after the container starts and before dispatching the prompt. Credentials exist only in the opencode server process for the duration of the sandbox session and are destroyed with the ephemeral container. The alternative — forwarding keys as Docker environment variables — exposes them to any tool the agent uses (`env`, `/proc/self/environ`, file reads), violating the requirements document's mandate that agents cannot read their own API keys. Delegating credentials to opencode's own auth management keeps the key at the HTTP boundary where opencode maintains it, rather than on a filesystem the agent's tools can probe.
